# Art spec

Everything an artist needs to draw sprites that drop straight into the game.
All numbers below are read out of the code, not remembered — regenerate them
any time with the snippet at the bottom.

**Status: World 1 is finished.** Every piece of art the game knows how to draw
is drawn — 56 of 56. Both brothers in all five forms, every enemy, the boss,
the hazards, the props, a nine-tile Boro Park tileset, three-layer parallax
backdrops in day / dusk / night, the meat board, the checkpoints, the world map
and the HUD icons.

Art still lands one piece at a time and nothing about the physics changes.
Anything missing from `src/config/sprites.ts` or `src/config/scenery.ts` falls
back to a rectangle of exactly its hitbox size, and the `available-art` Vite
plugin means the game only ever requests files that exist — so adding a sheet is
dropping a PNG into `public/`, with no code change and no restart.

`npm run check:art` holds every file on disk to the sizes these registries
claim, and fails the build when they drift.

Sprites are generated by `tools/art/generate.py`, which authors them as text
grids — one character per pixel — and renders PNG sheets. No binary asset is
hand-edited, so a recolour or a restyle is a diff rather than a redraw.

```bash
python3 tools/art/generate.py --out public/sprites
```

**To add a form**, draw it in `generate.py`, output a sheet, and add one entry
to `src/config/sprites.ts` giving its texture key, frame size and which frame
index is which pose. The game picks art up automatically wherever it exists and
falls back to a rectangle everywhere it does not — so a half-finished art pass
never breaks the build.

## The grid

| | |
|---|---|
| Tile size | **16 × 16 px** |
| Internal resolution | **320 × 180 px** (20 × 11.25 tiles) |
| Scaling | Whole screen is scaled up to fit the window, nearest-neighbour |
| Style | 16-bit pixel art, SNES era (§9) |

320 × 180 is exactly 16:9 and multiplies cleanly: ×4 = 1280×720, ×6 = 1920×1080.
**Draw at 1×.** Do not pre-scale anything — the game scales the whole frame at
once, and pre-scaled art will end up soft next to art that isn't.

### Tilesets and backdrops

One nine-tile set per world — `five_towns_tileset`, `catskills_tileset`,
`meah_shearim_tileset` — with the individual tiles in `public/tiles/`.

Backdrops follow World 1's rules exactly (320 × 180, seamless, opaque to the
bottom edge) but are named per world: `bg_sky_<world>_<v>`,
`bg_far_<world>_<v>` at ~0.25, `bg_near_<world>_<v>` at ~0.5. Variants are
`day`/`dusk` for the Five Towns and Meah Shearim, `day`/`night` for the
Catskills — the night set is for 3-3, the limited-visibility level.

## Origins

**Characters, enemies and crates are anchored at their feet** — origin
`(0.5, 1)`, i.e. bottom-centre. A sprite grows upward when the form gets
bigger, which is why growing never shoves anyone through a floor.

Coins and flames are centred, origin `(0.5, 0.5)`.

---

## Frames and padding

Right now each sprite frame is exactly its hitbox. **Real art does not have to
be.** Hair, a hat brim, a swinging lulav and a flame trail can all overhang,
and they should — a character whose art stops exactly at its collision box
looks stiff.

Recommended approach:

- Pick one frame size per character per form and keep it constant across every
  animation in that set.
- Leave **4–6 px of margin on each side and above** the hitbox. For Mendy Small
  that means roughly a **24 × 28** frame around a 14 × 22 box.
- Keep the feet on the bottom edge of the frame and the body horizontally
  centred. The game positions by the feet.
- Hand over the frame size with the art and the hitbox is set separately in
  code — one line per form.

### How to add a piece

Drop the PNG into `public/` under the path the registry names and it appears —
no code change, no registry edit, not even a dev-server restart, because the
`available-art` Vite plugin watches the directory. Frame sizes live in
`src/config/sprites.ts` (actors) and `src/config/scenery.ts` (backdrops,
furniture, interface), and `npm run check:art` fails the build if a file stops
matching the size its registry claims.

Two rules the backdrop layers have to keep, both learned by testing:

- **320 px wide and seamless left-to-right.** A layer is drawn into a sprite
  pinned to the camera and scrolled by moving the texture inside it, so a seam
  appears once per screen, forever. The build rejects any other width.
- **Opaque to the bottom of the frame.** Layers slide *down* as the camera
  climbs, so transparency along a layer's base becomes a visible horizontal cut
  in a level like 1-2.

## Licensing — non-negotiable (§2)

- **No Nintendo asset, sprite, sound, name or character.** Not as a placeholder,
  not as reference kept in the repo, not "temporarily".
- Anything third-party must be free for commercial use (CC0, CC-BY, or an
  explicit permissive licence) and goes in `CREDITS.md` with its source URL and
  licence **at the moment it is added**.
- AI-generated pixel art touched up by hand is fine and is the plan for
  characters, enemies and bosses, since nothing Jewish-specific exists in free
  asset packs.
- Environments and tiles were expected to come from free packs; in the event
  every tile in World 1 is original work out of `generate.py` too, so nothing in
  this repository is third-party and `CREDITS.md` has no asset entries to make.
  If a later world does pull from a pack, Kenney.nl is CC0 and the safest start,
  and it gets a `CREDITS.md` row the moment it lands.

## Regenerating these numbers

```bash
npx tsc --ignoreConfig src/config/Tuning.ts src/config/enemies.ts \
  --target es2022 --module esnext --moduleResolution bundler \
  --outDir /tmp/spec --skipLibCheck
```

Then read `TILE`, `CHARACTERS` and `TIERS` out of `/tmp/spec/config/Tuning.js`:
a form's size is `round(bodyWidth × widthScale)` by
`round(bodyHeight × heightScale)`, and crouched height is that height times
`crouchHeightFactor`.

Enemy, hazard and boss hitboxes are `bodyWidth` / `bodyHeight` in
`src/config/enemies.ts`, `src/config/hazards.ts` and `src/config/bosses.ts`.
Frame sizes are in `tools/art/manifest.json`, which `npm run check:art` holds
the PNGs and `src/config/sprites.ts` to.
